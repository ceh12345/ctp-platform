# Beta Updates

Working-doc folder for beta-partnership communication — plain-language summaries of what we've delivered, what we've tested, and what it unlocks for the partner.

## Audience

Stafford Engineering (and future beta partners) plus internal non-developer stakeholders. Written so someone who hasn't read the code can understand the outcome.

## What belongs here

- **Phase / sprint close-out summaries** — frozen snapshots of what a phase delivered, from the partner's perspective.
- **Beta status updates** — periodic "here's where we are" notes suitable for email or meeting agendas.
- **Pre-demo briefs** — what we'll show, what questions to expect, what limits to acknowledge.

## What does NOT belong here

- Living technical specs → those stay in `docs/sprints/`.
- Architecture diagrams, code snippets, file-change tables → `docs/sprints/` or `docs/` proper.
- Internal design debates → working-doc/scratch files, not here.

## Lifecycle

Documents in this folder are **frozen as of their close date**. If the underlying sprint evolves later, the beta-updates doc doesn't update — it remains a historical record of what was communicated (or communicable) at that point.

## Naming

`phase-<N>-<slug>.md` for sprint close-outs. Freeform for other notes, but prefix with a date (`YYYY-MM-DD-<slug>.md`) so the folder sorts chronologically.
